# AGENTS.md — stt-cursor

## Обзор проекта

**stt-cursor** — это инструмент непрерывной диктовки для Linux, который захватывает звук с микрофона через PulseAudio/PipeWire, выполняет офлайн-распознавание речи с помощью Google SODA (через `gasr/`, автопунктуация из коробки), восстанавливает IT-термины пост-слоем `term_fixer.py` и вставляет текст в позицию курсора с помощью `xclip` + `xdotool`. Финальные сегменты по умолчанию сохраняются парами «SODA → вставленный текст» в локальные JSONL-файлы `history/`.

- **Язык**: Python 3.14.2
- **Менеджер пакетов**: `uv`
- **Целевая платформа**: Arch Linux / Xfce / PulseAudio или PipeWire (X11)
- **Точка входа**: `main.py`
- **Вспомогательный**: `dictation-toggle.sh` (bash-скрипт переключения для привязки к глобальной горячей клавише)

## Команды

```bash
uv sync              # Установить зависимости (создаёт .venv)
uv add <package>     # Добавить зависимость в pyproject.toml
uv run python main.py  # Запустить приложение
.venv/bin/python main.py  # Запустить напрямую (быстрее)
python3 main.py --no-history  # Запустить без записи истории
bash dictation-toggle.sh  # Включить/выключить диктовку (привязать к горячей клавише)
bash dictation-toggle.sh --no-history  # Запустить через переключатель без истории
```

**Обработка ошибок**

## История диктовки

- По умолчанию каждый запуск создаёт JSONL в `history/`; после успешной вставки записывается пара «финал SODA → точная вставленная строка». PARTIAL, аудио и оконный контекст не сохраняются, сетевых вызовов нет.
- `history/` и её содержимое нельзя коммитить. Отключение: `python3 main.py --no-history` или `bash dictation-toggle.sh --no-history`.
- Запись делается после вставки и сразу сбрасывается через `flush`; `_cleanup()` закрывает файл. При изменениях не потерять эти гарантии.
- Ошибка истории должна предупреждать один раз и отключать запись до перезапуска, не прерывая диктовку и не мешая вставке.

## Системные зависимости

Эти зависимости **не** управляются через uv и должны быть установлены в системе **только через pacman**:
- `python-protobuf` — обязательно: `gasr/gasr.py` запускается под системным `/usr/bin/python3` и импортирует `google.protobuf`
- `parec` — захват звука PulseAudio/PipeWire (`pipewire-pulse` или `pulseaudio-utils`)
- `xclip` — управление буфером обмена (X11)
- `xdotool` — эмуляция клавиатуры X11
- `notify-send` — десктопные уведомления (libnotify)
- `libc++` — требуется бинарной `libsoda.so`

**Запрет:** никогда не ставить Python-зависимости этого проекта через `pip` в системный Python. При мажорном обновлении Python (например, 3.13 → 3.14) pacman пересоздаёт `/usr/lib/python3.X/site-packages`, и pip-установленные модули теряются — диктовка перестаёт запускаться с `ModuleNotFoundError: No module named 'google'`. Pacman-пакеты при таком обновлении пересобираются автоматически.

## Известный аппаратный сбой: Bluetooth-микрофон (Realtek RTL8821C)

- При пробуждении BT-источника из suspend (wireplumber) может зависать SCO-транспорт гарнитуры: pipewire показывает источник RUNNING, но байты не идут (`parec` отдаёт 0 байт), SODA пишет `Pipeline lagging` и не выдаёт ни одного финала. В рабочих сессиях строки `Pipeline lagging` не бывает — это надёжный детектор.
- `main.py` ловит это watchdog'ом по stderr gasr: передёргивает профиль BT-карты и перезапускает пайплайн (до 2 попыток), затем просит переподключить гарнитуру.
- **Нельзя** передёргивать профиль BT-карты, когда дефолтный источник — не `bluez_input` (например, при просмотре видео через гарнитуру источник другой): переключение профиля обрывает A2DP-воспроизведение.
- **Нельзя** делать превентивные проверки микрофона до старта пайплайна: они добавляют секунды к каждому запуску и ложно срабатывают на не-BT источниках (встроенный микрофон, виртуальные микрофоны). Старт и остановка должны оставаться мгновенными — починка только по факту сбоя.
- stderr gasr идёт через watchdog-поток (PIPE), а не наследуется напрямую: при изменениях не сломать переливание строк в лог.
