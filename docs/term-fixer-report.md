# Отчёт о пост-слое восстановления IT-терминов

## Что реализовано

- `term_fixer.py` предоставляет API `fix_text()` и stdin/stdout CLI. Работает полностью офлайн и использует только стандартную библиотеку Python.
- `terms_map.json` содержит канонические формы, точные варианты ошибок, контекстные якоря и вето. Fuzzy-матчинг не добавлялся: точных правил достаточно для всех принятых фикстур, а риск ложных замен и новых зависимостей ниже.
- Фразы сопоставляются без учёта регистра и только на границах слов; более длинные варианты обрабатываются раньше коротких. Контекст ограничен текущим сегментом.
- `main.py` вызывает `fix_text()` сразу после существующей `process_text()`. Голосовая пунктуация сначала превращается в символы и очищается от лишних пробелов, затем восстанавливаются термины. Сам `process_text()` не изменён.
- Узкое правило `pythonka wait` → `python с async await` закрывает фикстуру 8; отдельное `wait` не заменяется. Варианты `onnx` исправляются только при наличии `huggingface` в том же сегменте.
- `питон` исправляется только при IT-якоре и отсутствии животных/бытовых вето. `сода` и `дока` не имеют правил замены.

## Согласованное изменение фикстуры 5

Исходная спецификация одновременно требовала `genix` → `nginx` и оставляла `genix` без замены в `Проверил логин genix`. Пользователь выбрал вариант **всегда заменять `genix` на `nginx`**, поскольку `nginx` в его речи встречается чаще. Поэтому ожидаемый результат фикстуры 5 в тестах: `Проверил логин nginx и перезапусти systemd unit.` Это отклонение от исходного ожидания сделано явно, а не подгонкой теста.

## Метрики на фикстурах

Term recall — доля ожидаемых терминов из словаря, присутствующих в тексте как целые фразы. Регистр не учитывается. Каждое ожидаемое вхождение считается один раз; `Wireguard` не входит в знаменатель, потому что для него нет правила. «До» — исходный вход пост-слоя, «после» — фактический вывод `fix_text()`.

| Набор | До | После |
|---|---:|---:|
| Обязательные терминальные фикстуры 1–12 и 15 | 1/20 (5%) | 20/20 (100%) |
| Английские фикстуры 16–17 | 3/5 (60%) | 5/5 (100%) |
| Все терминальные фикстуры | 4/25 (16%) | 25/25 (100%) |

До пост-слоя уже правильно распознаны `Python` в фикстуре 6, а также `exitbox`, `Squid proxy` и `huggingface` в фикстуре 17. Поэтому английный бейзлайн не равен нулю.

Эти 100% описывают только заданные фикстуры одного набора, а не качество на произвольной живой речи. Файл со 175 живыми транскриптами не передавался и в метрики не входил.

## Ложные срабатывания и идемпотентность

- На обязательных контрольных фикстурах 13–14: **0 ложных исправлений в 2 сегментах**.
- Дополнительные проверки `компост`, `яй` без пакетного контекста, отдельное `wait`, `Annex`/`Onyx`/`unks`/`songs`/`onks` без `huggingface`, `сода`, `Дока`, `комитете`, `яйца` и животные вето также прошли без ложных замен.
- Список обнаруженных ложных срабатываний на этом наборе пуст. Это не доказывает их отсутствие на любой другой речи.
- Повторный `fix_text()` не изменил выход всех **17/17** фикстур 1–17. Отдельный тест подтверждает сохранение уже канонической латиницы.

## Скорость и проверки

Проверка `python3 -m unittest discover -s tests -v`: **15 тестовых методов, все прошли**. Есть отдельные реальные вызовы CLI через `subprocess`, включая многострочный ввод и отсутствие перевода последней строки.

Замер в контейнере, Python **3.12.14**: 5 серий по 1000 проходов по 17 фикстурам, всего 85 000 обработок сегментов. Медиана **68.0 мкс/сегмент**, диапазон серий **67.7–69.1 мкс**. В замер входит повторное применение уже загруженных правил, но не запуск Python и первичная загрузка JSON.

Полный пайплайн с микрофоном и X11 в контейнере не запускался. Тесты выполнены на Python 3.12.14, а не на целевом Arch/Python 3.14.2; живая проверка остаётся следующим шагом на машине пользователя.

## Что не решено

- **Endpointing A6-natural:** отсутствие FINAL при наличии только PARTIAL не относится к пост-слою и не исправлялось.
- **Русская грамматика:** `репозитории`, `Провери`, `проверить` и подобные ошибки намеренно остаются без изменений.
- **Не-IT `коммит`:** `комит`/`коммит` заменяются без контекстного якоря, как допускает фикстура 15. В редком не-IT употреблении возможна ложная замена; `Дока` при этом не меняется.
- **`genix` как логин:** выбранная замена всегда в `nginx` может испортить редкое имя пользователя. Это осознанный компромисс, согласованный пользователем.
- **Пропуски `питон`:** без IT-якоря слово остаётся неизменным, поэтому часть настоящих упоминаний Python не будет восстановлена.
- **Новые формы ошибок:** точный словарь не обобщает незнакомые искажения. Fuzzy-матчинг не включался, поскольку на текущих фикстурах он не нужен и повышает риск ложных исправлений.
- **Контекст между финалами:** якоря и вето действуют только внутри одного финального сегмента; истории предыдущих сегментов нет.
- **Другие en-контексты `onnx`:** без `huggingface` варианты `Annex`/`songs` и подобные остаются как есть, чтобы не портить обычные английские слова.
- **Живое качество:** фикстуры отражают ошибки одного диктора и не заменяют расширенную проверку на 175 живых транскриптах или новых записях.
